# 15 — Record references (serialisable cross-branch / cross-tree edges)

> **Identity:** `@PLN15` — [loft-lang/plans#15](https://github.com/loft-lang/plans/issues/15)
> (`status:future` — the issue is the source of truth for lifecycle state). Slug `record-references`.

## Status

**Design LOCKED, build DEFERRED (2026-06-09).** Every design decision is resolved (§ Open
design questions: Q1/Q3/Q4/Q5 resolved, Q2 a Phase-04 detail); no implementation. **Deferred
pending a real consumer** — per the dogfood loop this builds only when a concrete situation
needs it, not on an imagined axis. Anticipated trigger: **large stores with many nested layers
and cross-branch links** — graph-shaped data that cannot be a pure tree; no such consumer has
emerged yet. Until then the design is parked here, ready to build from Phase 00.

The model: a store is an ownership **tree** — every field that points at another record is an
*owner* edge (inline sub-struct, collection backbone, collection element, closure
`ChildRec`). This plan adds the second kind: a non-owning **reference** to a record owned
elsewhere in the **same store** — a graph edge while ownership stays a tree. References
serialise as a **canonical path key** (the JSON `$ref` idea), generated by walking *up* the
offset-4 owner back-pointers — `Stores::path(db, tp)` (`src/database/format.rs:114`), already
built and idle, wired into no serialiser; reserved emission site is the TODO at
`format.rs:887`. Pre-flight ~50% bug yield expected on the canonicality + copy invariants when
build starts (the Stage-A matrix is the go/no-go).

## Goal

A field can hold a non-owning reference to another record in the same store, and that
reference round-trips through own-format + JSON serialisation **and** survives `copy_claims`
relocation (internal edges remap in-store and cross-store; reference-closed subtrees migrate
cleanly).

## The one invariant (the hypothesis the matrix must falsify)

> Ownership stays a tree: every record has exactly one owner, recorded as its offset-4
> back-pointer; a reference edge is **never** an owner. Therefore `path()` yields exactly
> one canonical key per record, and a record's identity *is* its position in the ownership
> tree — derived on demand, never a stored id.

The corollary is the design's leverage and the answer to the copy requirement: because
owner identity is **position-derived**, moving or copying a record moves its key for free
(`path()` re-reads offset-4 at the new home). The *only* thing that does not move for free
is a reference edge's stored rec-id (a `rec` is a store offset). So **all brittleness and
all the copy / cross-tree work is concentrated at reference edges** — one fragile construct;
everything else robust by construction. Full mechanism: [DESIGN.md](DESIGN.md).

## Composition matrix — Stage A

Write these as `/tmp` probes on `--interpret` **before** any implementation; the feature is
done only when every cell is green on **both** backends, and the probes graduate to
`tests/scripts/15-record-references.loft`. Axes touched: target **type-kind**,
**construction-path** (the user's headline requirement is the copy column), **depth**,
**null**, **backend**.

| # | Cell (axis varied) | Falsifies | Expected hazard |
|---|---|---|---|
| P1 | target type appears as a field in **two** parents (type-kind × uniqueness) | the canonical-key invariant | `path()` admits *"assumes the child is linked only once"* (`format.rs:137`) + forks on `parents.len()>1`; owner vs reference edge may be indistinguishable |
| P2 | referenceable record nested **3 deep** under collections + a directly-owned sub-record (depth) | walk-up completeness | an ancestor with no offset-4 → key truncates; confirms incremental storage cost is only the leaf |
| P3 | reference to a sibling that serialises **later** (construction-path: parse) | forward-ref resolution | needs the deferred-fixup pass |
| P4 | serialise a **subtree**, not from root (context) | key scope | root-relative key may be unresolvable from a subtree root |
| P5 | free the owner while a referencer lives (null / lifetime) | the lifetime model | `dep.is_empty()==owner` mis-frees a referenced owner |
| P6 | **copy** a vector of mutually-referencing records — relocate in-store **and** cross-store (construction-path: copy) | the headline requirement | internal edges not remapped; cycle re-copied; an external edge under cross-store copy must be a clean error, not corruption |

P6 expands into the copy edge-cases (internal fwd/back, external in-store, self-ref, cycle,
external-under-cross-store → must error cleanly) enumerated in [DESIGN.md § Copy](DESIGN.md).

## Phase ordering

1. **00** first — the matrix can kill or reshape the invariant cheaply.
2. **01 → 02** are the foundation (no edge type, no owner guarantee → nothing else builds).
3. **03 → 04** establish the path-key ⇄ resolve model; **05** reuses that same fixup
   abstraction in-memory (`rec→rec′` remap). Do 03/04 before 05 so the one fixup concept is
   designed once (the chokepoint that keeps the re-assertion count near 1).
4. **06** can proceed in parallel with 03–05 but gates the ship (no dangling).
5. **07** closes.

## Open design questions

1. **Reference representation** (01) — **RESOLVED (2026-06-09): same-store 4-byte rec-id**,
   `ChildRec`-like but non-owning; targets restricted to **standalone records** (never
   by-value vector elements or inline sub-structs). Keeps stores isolated (independent free /
   serialise / `clone_for_worker`) — that, not the 4-vs-12-byte cost, is the deciding factor.
   Cross-store references are deliberately unsupported.
2. **Key scope** (04): always root-relative, or relative to the serialisation root.
3. **Cross-tree external-edge policy** (05) — **RESOLVED by Q1**: a subtree copied
   **cross-store** must be reference-closed; an outbound (external) edge under cross-store
   copy is a clean error (or null). In-store relocation preserves external edges unchanged.
4. **Dangling-owner policy** (06) — **RESOLVED (2026-06-09): generation tag** (weak,
   non-owning reference). The referenceable record carries a generation counter, bumped on
   free; the reference captures the generation at set-time; resolve checks them and a stale
   reference reads null — safe even after the slot is reused (no ABA). Chosen over refcount +
   forbid (a free-blocking count makes the reference a co-owner, fights Q1's non-owning
   decision, needs maintenance at every set/copy/free, and can't reclaim cycles) and over
   tombstone + sweep (keeps a 4B ref but holds the slot until a sweep). Generation is touched
   at just **two sites** — bump on free, check on resolve — for O(1)-safe resolve with
   immediate slot reuse. Cost: a gen word per referenceable record + ~4B in the reference
   `(rec, gen)`. *Pivotable later* if the cost or the cycle/ergonomics trade shifts.
5. **Referenceability — declared vs inferred** (01) — **RESOLVED provisionally (2026-06-09):
   declared** (`ref struct T`; `&T` on an unmarked type is a compile error). Chosen for
   correctness-first: the declaration is the single source of truth that drives layout (boxed
   standalone record + owner + gen word) and gates all per-record cost, and it gives the loud
   compile error for free. **The programmer toll is an accepted cost, not a liked one.**
   *Revisit trigger:* once the system works correctly end-to-end, evaluate dropping the
   annotation — candidate path is **inferred + reported** (compute referenceability at
   `finish()` from `&T` occurrences, but have the compiler *report* which types it boxed and
   why, which removes inference's only real objection — the silent action-at-a-distance — and
   so removes the toll without the perf cliff being invisible).

Each resolution is recorded in `DESIGN_DECISIONS.md` or absorbed into [DESIGN.md](DESIGN.md).
