# @PLN146 F1 — the pack is a loft store, and it holds scenes

The phase gate for **F1**, and the schema every later phase stores into. The plan and its
other phases are in [README.md](README.md).

> **The schema now ships as the `assets` package** (`loft-libs-assets` branch
> `tuxedo-assets-package`, unmerged). The copy in `probes/` is this phase's frozen
> evidence — the gates below were run against it — and the package is what a consumer
> reads. See the plan's [README](README.md) § Status.

## The schema is the file format

[`probes/assets_schema.loft`](probes/assets_schema.loft) carries the whole thing. There is
no codec, no parse step and no serialize seam — the struct definitions *are* the layout,
which is what makes a pack readable by HTTP range with no server-side code
([REMOTE_STORES.md](../../REMOTE_STORES.md)).

**A pack is TWO stores, split by how each half is read.** That split is what
REMOTE_STORES.md already prescribes — *"mixing those two in one file makes the boot load pay
for the world"* — and [F2](README.md)'s gate is what forced it here rather than later:

| store | rooted on | read | holds |
|---|---|---|---|
| `pack.meta.store` | `Pack`, a wrapper struct | **whole**, at boot | `PageInfo` `Cell` `Seq` `Def` `Anim` `Scene` `Placed` |
| `pack.blobs.store` | `hash<Blob[bl_key]>` directly | **paged**, per key | every byte: page pixels, audio, fonts |

| type | what it is |
|---|---|
| `Blob` | raw bytes under a key — page pixels, audio, a font, a source PNG. The paging unit |
| `PageInfo` | a texture page's *shape*, and the blob key its pixels live under |
| `Cell` | one sprite's rect within a page, plus the origin the stage places it by |
| `Seq` | an animation: a run of cells in one page's grid. Mirrors `stage::Sequence` |
| `Def` | an object definition — GameMaker's *object*. A light carries its radius, colour and power here |
| `Anim` | one row of a definition's animation table, `(def, action, facing) -> sequence` |
| `Scene` | a room |
| `Placed` | a placed instance, `index<Placed[pd_scene, pd_order]>`. Fields mirror `stage::Place` |

The metadata half is a **wrapper struct on purpose**: `store_persist_bind`/`_copy` persists
the store a collection lives in, and a keyed field shares its container's store, so one call
writes one file carrying all seven collections. The bulk half **cannot** be a field — a
collection reached through one records the wrapper as the store's type, and the paged loaders
refuse such a store outright (loft#632). So the same fact that makes the metadata one file is
the fact that forces the bytes out of it.

Three decisions, settled by measurement rather than taste:

- **Bytes are `vector<u8>`.** Measured on a 100 000-element blob: `vector<u8>` writes
  100 688 bytes, `vector<integer>` writes 800 688. One byte per byte.
- **The blob is the paging unit, not the sprite.** A store's minimum image is 8 KiB, so a key
  granularity finer than an atlas page fetches a page's worth either way.
- **A page's dimensions are metadata, its pixels are bulk.** A loader that needs to know a
  page is 64×32 — to build UVs, to size a GL texture, to decide what to prefetch — gets that
  from the boot load without fetching a texel. One record holding both would have made every
  such question cost a page fetch.

**A light is a placed instance like any other.** `DefKind` says whether a definition draws or
lights; both are placed through the same `Placed` record, ordered per scene. That is the shape
a prefab needs and the shape @PLN147's editor edits — retrofitting it would have cost a format
break, which is why it is in the first cut.

**A walk cycle is asset data, not code.** `anim_of(pack, "goblin", "walk", 2)` answers
`"goblin_walk_n"` with nothing in a game's source holding the mapping, and an absent action
answers `""` rather than a plausible wrong sequence.

## The gate, and what it actually proved

`loft --interpret probes/f1_pack.loft` (also `--native`, and `--native-wasm` under
`wasmtime`) builds a pack, persists it, loads it back and compares. The strong form runs it
twice on different backends:

```sh
F1_KEEP_PACK=1 loft --native probes/f1_pack.loft      # writes both halves
loft --native-wasm pack.wasm probes/f1_pack.loft
wasmtime --dir . pack.wasm                             # reads what --native wrote
```

Result: **every asset byte-identical, every scene row intact, and one layout fingerprint on
all three targets** — interpreter, `--native` and wasm. The wasm run consumes the native
run's bytes, which is a stronger statement than two fingerprints agreeing: it proves the
agreement over a file rather than over a derivation.

The demo pack weighs 19 104 B of metadata against 19 720 B of art, which is the wrong ratio
for a real game and the right one for a gate: it means the metadata half is exercised, not
rounded away.

**The fingerprint is derived, not written down.** The phase names
`type_layout_fingerprint`, which is an internal Rust function with no loft-visible API
(`src/native_lib.rs:1925`) — so the gate cannot be written the way it was filed. It is built
instead from the pack's own types by reflection (`type_named` → `TypeInfo.size` and each
field's name, type, position, kind and nullability, `layout_descriptor()`), which is a
*stronger* fingerprint than the internal one: that hashes name, size and alignment; this
hashes every field's position. A field that moved four bytes would slip past the first and
not the second.

## What the phase found on the way

**A `store_load` that never returned.** Loading this pack hung — no diagnostic, no bound, on
a call that only reads a file. Compaction-on-load (**ON** by default; the comment above it
said "off") rebuilt the image into a scratch store and recorded the root block one word
shorter than it owned, and the allocator walks a block chain by stepping over each block's
size — so it stepped over nothing, for ever. Fixed at both chokepoints: the rebuild records
the size it was actually given, and the walk can no longer fail to advance. Guarded by
`tests/store_persist_loft.rs::compaction_on_load_returns_both_backends`; the mechanism is in
[CHANGELOG_TECHNICAL.md](../../CHANGELOG_TECHNICAL.md).

It needed a container of several keyed collections plus values big enough for a later claim to
reach the linear scan — which is to say it needed **exactly a pack**, and that is why F1 found
it and four years of other stores did not.

**`store_durable_seal` does not compile for wasm** ([loft#1063](https://github.com/loft-lang/loft/issues/1063)) —
its Rust body is `#[cfg(feature = "mmap")]` and the wasm generator emits the call anyway, so
the failure is a raw `rustc` E0599 naming `loft::store::Store`. Not a blocker here: a pack is
built on a desktop and only read in a browser, so the seal belongs with the packer. Worth
knowing because the shape is general — any `#native` stdlib entry cfg-gated out of a target
fails this way.

## What F1 hands the rest of the plan

- **F2** reads this file by range: `store_load_key_text(local, url, key)` over `Blob`,
  whose text key is why the `_text` form is the one to call.
- **F4** packs Brick Buster's `build_atlas()` output as a `PageInfo` + `Rgba` blob pair
  plus its `Cell`s.
- **F7** adds `vector<Rect>` per cell — [F7a](F7a.md) settled the shape as sixteen bands.
- **W6** hands the packer a rendered canvas instead of a decoded PNG; the `Rgba` blob is the
  same either way, which is what makes its gate a comparison rather than a judgement.
- **@PLN147** edits this store directly. Reloading it **is** hot reload.
