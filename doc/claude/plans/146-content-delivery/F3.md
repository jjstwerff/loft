# @PLN146 F3 — zero fetches inside a frame

The phase gate for **F3**. The plan and its other phases are in [README.md](README.md);
the pack it pages is [F1](F1.md)'s and the range reads are [F2](F2.md)'s.

## The policy, and why it is only three lines

Synchronous wasm cannot await and a round trip is about 40 ms, so a frame that discovers
it needs an asset stutters visibly. The cure is not a faster fetch — it is asking
earlier. `keys_near(pack, scene, x, y, radius)` answers every blob key a scene's
instances draw from, deduplicated because a page shared by forty instances is still one
fetch; `prefetch(into, source, keys)` pulls them and answers how many actually cost
something. A negative radius means the whole scene, which is what a small room and a
loading screen both want.

The phase's own effort note said it: *the instrumentation is the work*.

## The instrument: a differential, not a marker

`./probes/f3.sh` runs the **same program twice** against the same logging server — once
with `F3_FRAMES=0` and once with 60 — and compares the request counts:

```
boundary only : 11 | prefetch: 2 key(s) wanted, 2 fetched  0 frame(s), 0 byte(s) read
sixty frames  : 11 | prefetch: 2 key(s) wanted, 2 fetched  60 frame(s), 737280 byte(s) read
control (miss): 18 | prefetch: 2 key(s) wanted, 2 fetched  60 frame(s), 741376 byte(s) read
F3: 60 frames, 0 fetches — and the control proves that is a reading
```

The alternative was to write frame markers into the log and correlate two streams. This
needs neither: **the wire must not know whether the frames ran**. It also cannot be
fooled by a count that was going to be non-zero anyway, because the boundary's own 11
requests are subtracted by construction rather than by a threshold.

Three ways red, and the third is the one that matters:

- the boundary fetched nothing, so the instrument never saw the wire at all;
- sixty frames cost more requests than none did — a frame fetched;
- **the control did not**. `F3_MISS=1` makes one frame in sixty reach for a key nobody
  prefetched. It costs **7 extra requests** — a size probe, a header, the table page and
  the record's page, plus the miss walking the bucket chain. A gate that cannot see that
  is a gate that would report a broken policy as a working one, which is why the control
  runs every time rather than once when the harness was written.

## What the numbers say

The cave scene draws from **two** texture pages, so the boundary is two keys and 11
requests — F2 measured the shape of those: a probe, a header read, the table page and
the record's page per key, plus the schema sidecar. Sixty frames then read 737 280 bytes
entirely out of the local store.

A fetch inside a frame is **not a wrong answer** — the control's run draws 4 096 more
bytes and every one of them is correct. It is a *late* one, and lateness is invisible to
every gate that checks values. That is the whole reason this phase is a wire measurement
rather than an assertion.

## What it left for later, and what closed it

`prefetch` looped `store_load_key_text`, one traversal per key, because `store_load_keys`
— which *"opens the reader once and reuses its page cache"* — took `vector<integer>` and
had **no text-keyed sibling** ([F2](F2.md) measured the cost: the table page re-fetched
per key). A pack is text-keyed, so a ring of twenty keys was twenty traversals.

**[loft#1064](https://github.com/loft-lang/loft/issues/1064) closed it** —
`store_load_keys_text(local, path, keys)` — and `assets::prefetch` was reworked onto it,
measured, and then **reverted pending the loader reaching `main`**: the package's CI
builds loft from `loft-lang/loft@main`, where the function does not exist yet, so the
rework took a green PR to *"Unknown function store_load_keys_text"* across all three
suites. Re-apply once #1064 lands (`git revert` of the revert, and move the `loft` floor
in the same change).

The measurement stands. Twenty keys against the same 5.1 MB pack, two runs each,
identical both times:

| | loader calls | requests | bytes fetched |
|---|---|---|---|
| key-by-key | 20 | 81 | 5 308 416 |
| batched | **1** | **24** | **1 572 864** |

The loop fetched **more than the whole pack** to deliver 1.25 MB of it; the batch fetches
roughly the payload. 3.4× on this shape — stated as a measurement rather than a ratio,
because it depends entirely on how the ring's keys fall across pages.

The contract did not change, deliberately: resident keys are filtered **before** the
call, because the loader answers how many it FOUND and a caller wants how many it PAID
FOR. Handing it a key already in hand would re-read it and report a cost that was not one
— which is the number this gate asserts is zero.

⚠ **The sequencing lesson, since it cost a red PR:** a library may only call what is on
the loft its CI builds, not what is on the branch its author is standing in. Check
`git show origin/main:default/*.loft` for the symbol before depending on it.
