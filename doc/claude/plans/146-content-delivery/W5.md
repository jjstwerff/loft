# @PLN146 W5 — the metric channel, and an exit status that is a verdict

The phase gate for **W5**. The plan and its other phases are in [README.md](README.md);
the renderer this measures is [W2.md](W2.md) / [W3.md](W3.md) / [W4.md](W4.md).

## The gate

```sh
corpus/w5.sh              # 7 scenes, both backends
corpus/w5.sh --control
```

**7 scenes, and both halves agree**: the report `drawing` prints is byte for byte the
oracle's own `stats.txt` blocks, and the exit status matches `draw.py --once`'s. The
control — a bare `~` judged at 0.5 of the paper instead of 0.02 — turns exactly four
readings red (one report and one exit code, on each of the two lanes), which is the
number it must.

Six of the seven scenes are new and live in [`corpus/checks/`](corpus/checks). They exist
because the corpus has **one** scene with checks in it (`old_woman.draw`, four of them,
all passing), so every other form the grammar has — a tolerance clause, a landmark, a
term with arithmetic on it, each comparison operator, and each way a name can fail to
resolve — had to be written down to be measured at all. The seventh scene is
`old_woman.draw` itself: the same thing end to end at full size, on the compiled lane.

`drawing`'s own suite is 36 tests, green on both backends.

## What the phase adds

`landmark` and `check` were already parsed and carried; they are now **measured**.

- `eval_checks(sk)` → one `Check` per line: the two sides as measured, the verdict, and
  the report line in `draw.py`'s spelling.
- `metric_report(sk, results)` → the report: what did not parse, what was recognised and
  not drawn, where every named element sits, and how each check came out.
- `scene_ok(sk, results)` → the `--once` verdict.
- `examples/draw.loft` → the runnable: render one scene, print the report, exit non-zero
  naming the first thing that is wrong.

The point is not the checks; it is that **something which cannot look at the PNG can
still know the sprite is wrong**. A metric report costs a read where a picture costs a
look, and an exit status costs neither.

## Finding 1 — a report is a wire format, so it is pinned rather than described

The oracle's report is not decoration: `stats.txt` is what an agent reads after a render,
and two tools that both "report the checks" in their own words cannot be diffed. So the
gate compares the text byte for byte, and the package's own tests pin the exact lines
(`check: a.cx ~ 0.2  ->  0.200 vs 0.200  d=+0.000  PASS`) rather than asserting that a
check passed.

That is what turned three details into findings instead of guesses:

- **The tolerance clause comes OFF the echoed claim.** `check head.cx ~ 0.333 tol 0.04`
  reports as `check: head.cx ~ 0.333` — the tolerance is applied and not repeated.
- **`tol` is the one word in the grammar that is case-SENSITIVE.** Every other regex in
  `draw.py` carries `re.I`; the tolerance one does not, so `TOL 0.04` is not a tolerance
  clause, it is part of the right-hand side (and then fails to resolve).
- **The element table is ordered by first INK, not by first mention.** The oracle keys it
  by name in a dict, and a dict's order is insertion order — an element is inserted when
  a mark first contributes to its box. A scene that writes `name late` before `name early`
  and draws `early` first reports them the other way round from the parse order, which is
  why `Elem` gained `first_at` and `checks/order.draw` exists.

## Finding 2 — loft's `+` format flag is dropped on a float

`draw.py` writes the delta as `{delta:+.3f}`, so a passing check reads `d=+0.002`. In
loft, `"{d:+.3}"` renders `0.002` — the sign flag applies to integers (`{n:+}` is `+42`)
and is silently ignored on a `float` or a `single`, identically on both backends.

`formal/formatting.md`'s `(F-Spec)` says `+` means *"always show a sign on a number"*, and
a float is a number, so this is a rule deviation rather than a documented limit — the
float format opcodes carry no `plus` operand at all, so the parser accepts the flag and
has nowhere to put it. Filed as [loft#1087](https://github.com/loft-lang/loft/issues/1087).
The package writes the sign itself (`signed3`), because a library builds against RELEASED
loft and cannot wait for a format fix.

## Finding 3 — the port does NOT copy the oracle's silence about a mark it cannot draw

`draw.py` draws everything it parses, so `--once` has no notion of a mark that was
recognised and skipped. This build has one: `Petals` parses and is listed in
`Sketch.deferred` because no corpus scene uses it.

A renderer that is short of a mark the scene asked for cannot answer "fine", so
`scene_ok` fails on a deferred mark and the CLI names it. `checks/deferred.draw` is the
scene where the two tools are MEANT to disagree — the oracle draws the petals and exits
0, this exits non-zero — and the gate asserts that disagreement rather than diffing it,
which is the only way a deliberate difference stays visible instead of becoming a
tolerated red.

## Finding 4 — a field default that names a constant declared below it is an ICE

Writing `tol: float = DEFAULT_TOL` where the constant is declared later in the file
aborts the compiler:

```
Incorrect var DEFAULT_TOL[65535] versus 8 on n___dflt_Check_tol [src/state/codegen.rs:3904]
```

65535 is the not-found sentinel, used as a variable slot. Move the `const` above the
struct and the same program runs. Filed as
[loft#1086](https://github.com/loft-lang/loft/issues/1086); the package spells the literal
for now.

## What is deliberately not here

The two `stats.txt` blocks that measure the rendered PICTURE — the density map and the
composition notes. `w2.sh` already diffs the picture pixel for pixel; this channel
measures the SCENE. Nothing else in the grammar is missing: `landmark`, `check`, every
operator, the tolerance and the right-hand-side arithmetic are all here.

`draw.py`'s other mode — watch the file, redraw on save — is not ported either. A redraw
loop belongs to an editor ([@PLN147](../147-content-editor/README.md)), not to a gate, and
`--once` is accepted as a flag so a command line written for the oracle runs here.
