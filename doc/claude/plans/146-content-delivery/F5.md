# @PLN146 F5 — three font sources, one declaration

The phase gate for **F5**. The plan and its other phases are in [README.md](README.md);
the mechanics it makes declarative are in [FONTS.md](FONTS.md), and the ordering half is
[F6](F6.md).

## The declaration

```toml
[[font]]
family = "PressStart2P"                 # the CSS family AND the lookup key
native = "fonts/PressStart2P.ttf"       # what the program passes to gl_load_font
url    = "fonts/PressStart2P.woff2"     # our own server  -> @font-face
# stylesheet = "https://fonts.example/css2?family=…"   # a provider -> <link>
```

Three sources, one shape: a family the browser already has declares neither `url` nor
`stylesheet` and the page brings nothing; a font file we serve becomes an `@font-face`;
a provider's stylesheet becomes a `<link>`. `native` is the same font for every other
target — the file beside the game. A library declares fonts the same way and its
declarations reach the page through the same route as `[wasm.bridge] host_js`.

`src/html_fonts.rs` owns all of it: validate, emit the `<head>`, emit the await.

## The gate

`tests/html_fonts.rs`, four tests, three of them in headless Chromium:

```
each_declared_font_source_resolves_to_the_requested_family   (F5)
the_boot_await_holds_the_program_until_a_slow_font_has_arrived   (F6, + its control)
a_declared_font_reaches_the_emitted_page                     (the wiring)
a_drifting_family_is_refused_before_the_build                (the refusal)
```

**It asserts the resolved family, not that text drew** — text draws in a fallback
perfectly well, which is the entire failure being closed. The page loads
`doc/loft-gl-wasm.js`, hands it the emitted `<head>` and the emitted await, and reads
what `gl_load_font` actually resolved out of the bridge's own record
(`globalThis.loftFonts`).

Proven red: with `head_html` returning nothing, the two brought families go unresolved
and the gate fails. That check ran before this doc was written, because a green gate
that has never been red is not evidence.

## `document.fonts.check` cannot answer the question — measured

The gate needed a way to ask *did this family resolve?* and the obvious API does not
answer it. In headless Chromium:

| asked | answer |
|---|---|
| `check('16px "NoSuchFamilyXYZ"')` | **`true`** — a family nothing declares |
| `check('16px "LoftProbeFace"')` with its `@font-face` still loading | **`false`** |
| the same, after `document.fonts.load` | `true` |

So `check` is true for a font that does not exist and false for one that is on its way.
The instrument this phase uses instead is a **measurement against two generics**: a
family the browser has overrides both, so `"X", monospace` and `"X", sans-serif`
measure the same; one it does not have follows each and they differ. It has a working
negative (`NoSuchFamilyXYZ` → not resolved) and its precondition is asserted (the two
generics must measure differently at all).

## What that measurement found in loft

**`familyFor` had it backwards, and the exact-font path was the broken one.** The
bridge resolved a font's CSS family by asking `check` whether the page had it:

```js
if (document.fonts.check('16px ' + quoted)) return quoted + ', sans-serif';
// …else a generic guessed from the name
```

Read against the table above, that says: a page that declared **nothing** took the
exact-font branch (check is vacuously true), and the one page that had **brought its
own font** took the generic branch — and the answer is cached per handle, so a single
early `gl_load_font` locked that handle to `sans-serif` for the whole run. The
name heuristic (`mono` → `monospace`) was unreachable in every other case, so a
missing `DejaVuSansMono` fell back to a proportional face rather than a fixed-pitch
one.

The fix is smaller than the bug: name the requested family **and** the generic, and let
CSS choose — `"X", monospace`. A family that resolves wins; one that does not falls to
the generic its name suggests. Nothing is cached that a later frame cannot correct.

Beside it, the silence is closed too: `gl_load_font` measures the family it just
registered and `console.warn`s once when it did not resolve, naming the family and the
generic that will draw instead. A warning, not a refusal — a remote font is a
third-party dependency and degrading is right ([FONTS.md](FONTS.md)); what was wrong
was doing it quietly.

## The build-time half

`family` must equal the base name of `native`, because that base name is the *only*
thing the browser sees — `gl_load_font("fonts/Press Start 2P.ttf")` reaches the page as
`Press Start 2P` and nothing else. A page that registers `PressStart2P` while the
program asks for `Press Start 2P` draws in a fallback, and no diagnostic anywhere says
so.

So the drift is **refused**, and refused **before the wasm build** — a manifest that
cannot produce a working page should not cost a compile first. The refusal names both
spellings and which one the browser will use. Refused with it: a family that is empty,
one carrying characters that would break out of the page's CSS or HTML, one source
declared twice over (`url` *and* `stylesheet`), and the same family declared twice with
different sources. Two identical declarations are not a conflict — an app and a library
it uses may name the same font.

## Two things the gate pins that the phase did not name

**A library's declarations reach a consumer's page.** A library that draws its own text
declares the font it draws with, and that travels the same route as `[wasm.bridge]
host_js` — registered at both manifest sites, because a library reached through one and
not the other would lose its browser half silently. The end-to-end test builds a page
whose font comes from a path dependency and reads it back out.

**A page that imports only `loft_io` gets no font block.** That shell has no text bridge,
so an `@font-face` in it would cost a fetch for a font nothing can draw with. Declaring a
font in a program that draws no text is therefore quiet, and harmless.

## What it leaves for later

The check is on the manifest, not on the call: a program that declares
`native = "fonts/Foo.ttf"` and then calls `gl_load_font("other/Bar.ttf")` is not caught,
because the argument is a runtime value. The declaration is what a game should pass —
`native` exists so there is one spelling of the path — but nothing enforces that today.
