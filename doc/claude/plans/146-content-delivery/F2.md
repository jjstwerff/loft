# @PLN146 F2 — the same source, from disk and from a URL

The phase gate for **F2**. The plan and its other phases are in [README.md](README.md);
the schema it pages is [F1](F1.md)'s.

## The gate

`./probes/f2.sh` builds a pack, reads two keys out of it from a local path, starts a
static file server, reads the same two keys from a URL, and compares — the answers and
the wire.

```
local: hit.ogg=2048 ui.woff2=4096 checksum=768174 resident=2 absent-key=false
url  : hit.ogg=2048 ui.woff2=4096 checksum=768174 resident=2 absent-key=false
server: 6 page(s) + 6 probe(s), 0 whole-file, 394341 of 4235232 bytes (9%)
F2: same answer from disk and from a URL, and only the pages the keys touch
```

**Nothing in the program changes but `$F2_SOURCE`.** `store_load_key_text` takes a local
path and an `http(s)://` URL interchangeably, so "develop against a file, ship against a
CDN" is not a porting step.

It goes red four ways, and a control that reads the pack whole
(`store_load_url_trusted`) trips three of them at once — 1 whole-file request, 112 % of
the file, and `resident=68` where the paged reader has 2:

- the two runs disagree about the bytes;
- the pack was requested whole;
- more than a quarter of the file crossed the wire;
- a data read was not a whole 64 KiB page (a reader that fetched per record would
  answer the same bytes at one round trip each, and the byte total alone would not say so).

## What it costs, measured

Per **present** key: a 1-byte size probe, a 4-byte header read, the table page, and the
page the record sits on — **two 64 KiB pages**. An **absent** key costs about five, the
miss walking the bucket chain. Against a 4 MB pack that is 3 % per key.

Two things the log says that the byte total does not:

- **Page 0 is re-fetched for every call.** Each `store_load_key_text` opens its own
  reader, so the table page is paid for once per key rather than once per traversal.
  `store_load_keys` exists to fix exactly this — *"opens the reader once and reuses its
  page cache"* — but it takes `vector<integer>`, and **there is no text-keyed sibling**
  ([loft#1064](https://github.com/loft-lang/loft/issues/1064)). A pack is text-keyed, so
  today N keys cost N traversals. That is the cost `F3`'s prefetch works around.
- **The schema sidecar is fetched whole**, once per call: 370 bytes, correctly, and the
  gate counts it apart from the pack so it neither hides nor false-fails.

## Two things that had to be fixed to get here

**A paged load refused any entry type with an enum field.** `bl_kind: BlobKind` was
enough to make the whole collection unreadable a key at a time, and the refusal blamed a
`vector<text>` the type did not have. Both halves were defects — the missing
`Parts::Enum` arm in `is_copyable_field`, and a refusal message that named the same two
types whatever the cause. Fixed, with the values checked rather than just the
acceptance; see [CHANGELOG_TECHNICAL.md](../../CHANGELOG_TECHNICAL.md).

**The pack had to become two stores.** The paged loaders refuse a store rooted on a
wrapper struct, and a collection declared as a field always records the wrapper as the
store's type (loft#632). That is what split F1's schema into a metadata container read
whole and a `hash<Blob[bl_key]>` rooted directly — the same split REMOTE_STORES.md
prescribes for cost reasons, arrived at here for a structural one.

## Two corrections to the phase as filed

**`python3 -m http.server` is the wrong server for this gate.** It ignores `Range` and
answers `200` with the whole body. loft reads correctly through that — it discards the
prefix to reach the offset, which is the deliberate fallback for a misconfigured host —
so a run against it proves the URL path works and says *nothing* about what crossed the
wire, which is the half the phase exists to prove.
[`probes/f2_server.py`](probes/f2_server.py) is 70 lines: it answers `206`, and it logs
every request so the gate can read the wire instead of trusting it.

**A 20 KB fixture cannot fail this gate.** The demo pack from F1 is a third of one
64 KiB page, so a paged read of it fetches everything and is right to. The first green
run was measuring nothing. The packer now pads to ~4 MB (`F2_FILLERS`, default 64), which
is what makes "9 % of the file" a number with something to say.
