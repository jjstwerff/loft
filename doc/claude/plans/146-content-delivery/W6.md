# @PLN146 W6 — a scene straight into the pack

The phase gate for **W6**. The plan and its other phases are in [README.md](README.md);
the pack is [F1.md](F1.md), the renderer [W2.md](W2.md).

## The gate

```sh
corpus/w6.sh              # three scenes, both routes, compared out of a written pack
corpus/w6.sh --control
```

**Three scenes, and the two routes produce the same atlas entry** — same page size, same
cell rects, the same page bytes, and the same derived collision proxy — with the
comparison made on what `pack_read` hands back rather than on what the packer had in
hand. `W6_BACKEND=--interpret` runs the same thing on the interpreter; both lanes are
green. The control moves ONE texel on the fileless route and the gate goes red on the
page bytes and on eleven proxy boxes.

Three scenes rather than one on purpose: a page holds more than one cell, and a placer
that ignored its grid step would still agree with itself on a single tile.

## The two routes

```
A  scene -> render -> save_png -> a FILE -> imaging decodes it -> texels -> pack
B  scene -> render ->                                             texels -> pack
```

Route A is what a packer had to do before this phase: `drawing` could only hand a picture
out as a PNG, so building an atlas from `.draw` scenes meant writing every sprite to disk
and decoding it again. Route B skips the file. The claim is that skipping it changes
nothing.

## What the phase adds — and where

Nothing in `drawing`: `render(sk)` already hands back a `Canvas`. What was missing was on
the other side, and it is three things in `assets`:

- `texels(words)` — the RGBA bytes of a row-major buffer of `0xAARRGGBB` words. Both
  routes end here: a `graphics::Canvas` holds exactly those words in `data`, and a PNG
  decoded by `imaging` answers them through `Pixel.rgba()`. **One conversion, not two** —
  which is what makes the two routes' agreement a fact about the routes rather than about
  two copies of the same arithmetic.
- `Tile` — a key, a size, and texels. Where the texels came from is deliberately not the
  package's business.
- `page_grid(...)` — lay tiles out in a grid page, blit them, and record one `Cell` each,
  with **the collision proxy derived from the alpha as the cell lands** ([F7](README.md)).
  So re-arting a sprite moves its hitbox with no hand edit, which is the whole point of
  deriving it.

`assets` still depends on nothing but `shapes`. That is why `texels` takes words rather
than a `Canvas` or an `Image`: the packer's library has no business linking a renderer or
a decoder, and a pack format that did would drag both into every consumer.

## Finding 1 — the packer the plan leaned on did not exist

This phase was cut as **S** on the sentence *"`F1`'s packer already premultiplies, pads
and places; this hands it a rendered canvas instead of a decoded PNG."* It does not.
`F1` shipped the schema, the two-store write and the paged read; `F7` added proxy
derivation over caller-supplied texels; `F4`'s vehicle drew one page and stored it whole,
with a ten-line `rgba_bytes` helper of its own. Nothing anywhere placed a cell.

So W6 is the placer as well as the route — still S, because a grid placer over
`vector<u8>` is fifty lines, but the premise it was cut on was false and the phase would
have been mis-scoped by anyone who trusted it. A plan's row is a claim about the tree,
and this one had gone stale between being written and being worked.

## Finding 2 — straight alpha, and the schema says so twice

`BlobKind::Rgba` promises PREMULTIPLIED texels. A page destined for
`SRC_ALPHA / ONE_MINUS_SRC_ALPHA` blending must not be premultiplied, so `page_grid`
writes `Bytes` — the same choice `F4`'s vehicle made and documented, now made once in the
library instead of once per packer.

The proxy derivation is indifferent to the convention: it reads the alpha byte, which is
the same byte either way.

The placer is `assets` 0.3.0 —
[loft-libs-assets#tuxedo-assets-w6](https://github.com/loft-lang/loft-libs-assets/tree/tuxedo-assets-w6),
additive over 0.2.0 in API and in data alike (the pack layout fingerprint is unmoved), 24
tests green on both backends.

## Still open, and named rather than done

`tools/brick-buster/pack_atlas.loft` still carries its own `rgba_bytes`, because it
builds against the RELEASED `assets` and this one is not published yet. Retiring it is a
one-line change the day the release lands.
