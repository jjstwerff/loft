# @F89 — Test runner (fn test_*, loft --tests / loft test)

## What it is

loft finds and runs your tests for you: any function named `test_*` is a test. `loft --tests <file>` (or `loft test` in a package) discovers them, runs each, and reports which passed. An `assert(...)` that fails marks the test failed.

## How it aids you

There is no test framework to install and no runner to wire up — name a function `test_something`, put `assert`s in it, and it runs. Tests sit right next to the code they check.

## Example

```
// mymath.loft
fn add(a: integer, b: integer) -> integer { a + b }

fn test_add()  { assert(add(2, 3) == 5); }
fn test_zero() { assert(add(0, 0) == 0); }
```

Run them with `loft --tests mymath.loft` — every `test_*` runs and its pass/fail is reported.


## What the runner actually picks up

Not the `test_` prefix — **arity**. `loft --tests` runs every function in the file that takes no parameters, counts each one in the total, and fails the file if any of their `assert`s fail. That includes a helper named anything you like, and it includes `main`:

```loft
fn setup() { println("SETUP RAN"); }
fn test_one() { assert(1 == 1, "ok"); }
```

```
$ loft --tests repro.loft
SETUP RAN
  ok    repro.loft  (2 fns: setup, test_one)
```

A function that takes a parameter is the only thing skipped, so a parameter — even an unused one — is today's way to say "not a test" (loft#1010). Exit codes are right either way: 1 when something fails, 0 when nothing does.
