# @F12 — Struct records — fields, `= default`, `computed`, `limit`/`not null`/`assert`

## What it is

A named type that groups related values together as fields. Create one by naming its fields; read a field with a dot. Fields can carry modifiers, and they are not all the same kind of thing — one is checked by the compiler, one at run time, and one only decides how the value is stored:

- **`const`** — set once at construction; assigning it afterwards is a compile error.
- **`= default`** — the value to use when a literal leaves the field out. Without one, an omitted field takes its type's zero.
- **`computed(expr)`** — worked out on every access and never stored, with `$` naming the record: `area: float computed(3.14159 * $.radius * $.radius)` follows `radius` for free and costs no space.
- **`assert(...)`** — a rule loft enforces at RUN time: a write that breaks it stops the program with `field constraint failed on <Type>.<field>`.
- **`limit(lo, hi)`** — chooses how the integer is STORED (`u8` *is* `integer limit(0, 255)`), and is not enforced. A value outside the range is neither refused nor reported — today it is dropped, wrapped, or stored as `lo`, depending on the width (loft#984). Write `assert(...)` when you want the range checked, or use a narrow type (`u8`, `i16`) when you want the compiler to demand a checked cast at every write.
- **`not null`** — deprecated and does nothing; a type is non-null by default and loft says so when it sees one.

## How it aids you

Instead of juggling several loose variables that belong together, you keep them in one named thing — easier to pass around, and the field names say what each value means. `const`, `assert(...)` and `computed(...)` put the rule next to the data it governs, so an identifier that must never change, a value that must stay in range, or a number derived from the others says so where it is declared rather than in every function that touches it.

## Example

```loft
struct Account {
    const id: integer,
    name: text = "unnamed",
    balance: integer limit(0, 1000000),
}

fn main() {
    a = Account { id: 7, balance: 250 };
    println("{a.id} {a.name} {a.balance}");   // 7 unnamed 250
    a.balance = 300;                          // an ordinary field changes
    println("balance {a.balance}");           // balance 300
}
```

`name` was omitted at construction, so it took its default. Assigning `a.id` is a compile error — a `const` field is fixed once the record exists.
