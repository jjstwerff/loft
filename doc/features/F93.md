# @F93 — Paged & remote store loading — read part of a dataset over HTTP range

## What it is

Read only the entries you ask for out of a store, instead of loading the whole file. `store_load_key` fetches one entry, `store_load_key_text` the text-keyed form, `store_load_keys` a batch, and `store_load_range` a contiguous span.

The path is a local file **or an `http(s)://` URL** — the same call either way, on every target including the browser. Over HTTP loft issues `Range` requests and pulls only the 64 KiB pages the lookup touches, so a 2 GB dataset on static hosting costs a few kilobytes to query. `store_load_url_trusted` takes a whole image when you want all of it; `store_load_url` does the same pinned to a SHA-256.

## How it aids you

Ship a large dataset as a plain static file — on a CDN, S3, GitHub Pages — and query it with no database server and no API in front of it. A game streams its world chunks, meshes and sounds as the player moves; a catalogue or gazetteer answers lookups without downloading itself. Because the same call takes a path or a URL, you develop against a local file and ship against a URL with no code change.

## Example

```loft
struct Part { const id: integer, name: text }

fn main() {
    all: hash<Part[id]> = [];
    store_persist_bind(all, "parts.store");
    all += Part { id: 7, name: "bolt" };
    all += Part { id: 91, name: "washer" };

    // Read back ONE entry — over HTTP this fetches only the pages it needs.
    one: hash<Part[id]> = [];
    if store_load_key(one, "parts.store", 91) {
        for p in one { println("found: {p.id} {p.name}"); }   // found: 91 washer
    }
    delete("parts.store");
    delete("parts.store.dschema");
}
```
