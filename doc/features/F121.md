# @F121 — Parser library (lib/parser)

## What it is

The `parser` library reads loft SOURCE at runtime and tells you whether it is well formed.

`parse(name, source)` is the whole entry point. `name` is the label that appears in the
diagnostics — it need not be a real file. The answer is the NUMBER of errors the source
contained, so `0` means it parsed cleanly; the diagnostics themselves go to the log as the
source is read.

⚠ Not to be confused with **@I58 Parser (two-pass recursive descent)**, which is loft's OWN
parser — the compiler stage that reads your program. This is a library your program calls to
read loft source of its own.

## How it aids you

It answers "is this loft?" without running anything, which is the question a tool asks:
validate a config written in loft syntax before acting on it, check a snippet your program
generated, or fail a test when a template stops compiling. Because the answer is a count and
not a crash, the caller decides what a bad input means.

With the `lexer` library it is also a starting point rather than a fixed tool: the two are
built to be reused, so you can keep the tokeniser and put your own grammar on top.

## Example

```loft
use parser;

fn main() {
    // `{{` and `}}` are how a brace survives a loft text literal — the source you
    // hand the parser is ordinary text.
    clean = parser::parse("snippet", "fn add(a: integer, b: integer) -> integer {{ a + b }}");
    println("errors in a good snippet: {clean}");   // errors in a good snippet: 0

    // A malformed snippet is counted, not thrown — the diagnostic goes to the log
    // and the caller decides what to do about it.
    broken = parser::parse("snippet", "fn add(a: integer -> integer {{ a }}");
    println("a malformed one is counted: {broken > 0}");   // a malformed one is counted: true
}
```
