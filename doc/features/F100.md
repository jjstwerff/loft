# @F100 — Dead-code lint — a local never read, and a write whose value is lost

## What it is

A lint that points out a local you never read, and a write whose value nothing ever uses — including the case where you copied a collection, changed the copy, and the change went nowhere.

## How it aids you

The dangerous half is the silent one. `d = self.data; d[i] = x` binds a **copy**, so the write is lost and the program keeps running with the original data. A published drawing library shipped every one of its primitives as a no-op through exactly that shape. The lint names the line instead of leaving you to notice the missing output.

## Example

```
advice: `d` is written but never read — the write is lost
  --> canvas.loft:12:5
   |
12 |     d[i] = colour;
   |     ^
```

Advice-tier, so it never fails a build; `LOFT_NO_DEAD_STORES=1` turns it off. Note that guarding with `if i < len(d)` does **not** count as reading `d` — a length cannot witness an element write.
