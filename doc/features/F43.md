# @F43 — Random numbers (rand_seed / rand / rand_indices)

## What it is

Reproducible pseudo-random numbers. `rand(lo, hi)` gives a uniformly distributed integer in `[lo, hi]` inclusive; `rand_seed(seed)` fixes the sequence; `rand_indices(n)` gives `0 … n-1` in a random order.

They live in the **`random` package**, not the always-loaded stdlib, so a program says `use random;` first. loft names the package for you when the call does not resolve.

## How it aids you

A seeded generator makes a random program *repeatable*, which is what makes it testable: seed it and the same run produces the same answer every time, so a shuffle or a sample can be asserted against a fixed expectation instead of a range. The generator is PCG64 and starts from a fixed default, so a program that never calls `rand_seed` is still deterministic — reproducibility is the default rather than something you opt into and forget.

`rand_indices(n)` is the one to reach for when you want *distinct* items. Drawing with `rand` repeatedly samples with replacement, so it can hand you the same index twice; a permutation cannot. Take the first `k` of it and you have `k` distinct items — sampling without replacement, and random iteration order, with no rejection loop.

`rand(lo, hi)` answers null when `lo > hi` or either bound is null, rather than guessing at an empty range.

## Example

```loft
use random;
fn main() {
    rand_seed(42);
    roll = rand(1, 6);
    assert(roll >= 1 && roll <= 6, "a die roll stays inside its bounds: {roll}");

    items = ["a", "b", "c", "d", "e"];
    order = rand_indices(len(items));
    assert(len(order) == 5, "one index per item: {len(order)}");

    // A permutation, so every index appears exactly once: 0+1+2+3+4 = 10.
    sum = 0;
    for i in order { sum += i; }
    assert(sum == 10, "rand_indices is a permutation, not a sample: {sum}");

    // Three DISTINCT items — `rand` three times could repeat one.
    println("{items[order[0]]} {items[order[1]]} {items[order[2]]}");  // c a e
}
```

## One rule to know

The sequence is per thread. `rand_seed` seeds the thread-local generator, so seeding on one thread does not make a `par` worker reproducible — seed inside the work if you need that.
