# @F16 — Functions & declarations (`pub`, parameters, return)

## What it is

A function is a named piece of logic you can run whenever you like. You list what it takes in, say what it gives back, and write the steps once — then call it by name as often as you want. Mark a function `pub` to share it so other files can use it too — `pub` is what crosses a file boundary even inside one package, so an unmarked helper stays private to the file that declares it.

A declared result has to arrive on **every** path: a route that falls off the end of a `-> T` function is a compile error (*"expected text, got void on return from block"*), not a zero value slipped in for you.

The other direction is not checked. **A result you ignore is discarded in silence** — `edit(doc);` as a statement compiles, runs, allocates whatever it allocated, and throws the answer away. For an API of pure functions that is the whole failure mode, so bind the result.

## How it aids you

Write a calculation or task in one place and reuse it everywhere, instead of copying the same lines around. Each function has a clear name and a clear result, so your program reads as a list of intentions rather than a wall of detail — and `pub` lets you build a toolbox that other parts of your code can call.

loft reads the shape of the function back to you as you write it: code after a `return` is reported (`unreachable-code`), and a function whose nesting has grown past what a reader can hold is too (`function-complexity` names the deepest line, where a split pays).

## Example

```loft
pub fn square(n: integer) -> integer {
    n * n
}
fn greet(name: text) -> text {
    "Hello, {name}"
}
fn main() {
    println(greet("world"));               // Hello, world
    println("square(6) = {square(6)}");    // square(6) = 36
}
```
