# @F4 — Ranged/width integer types (u8/i8/u16/i16/i32/u32)

## What it is

Besides the everyday `integer`, loft offers smaller number types sized to their range: `u8`, `i8`, `u16`, `i16`, `i32`, `u32`. Each holds whole numbers within fixed bounds and takes up less space.

## How it aids you

When you store many numbers you know stay small — a colour channel (0..255), an age, a year — these compact types keep your data small and your intent clear, while you still write and read them like ordinary numbers.

## Example

```loft
fn main() {
    level: u8 = 200;      // fits in a single byte (0..255)
    year: u16 = 2026;     // fits in two bytes
    temp: i8 = -40;       // small signed value
    println("{level} {year} {temp}");   // 200 2026 -40
}
```


## Where the bounds are enforced, and where they are not

The bounds hold at the declaration and in storage, and are absent on a local reached by a compound operator.

| position | out-of-range | result |
|---|---|---|
| declaration — `l: u8 = 300` | | refused: *"cannot implicitly narrow integer to u8"* |
| written-out assignment — `l = l + 10` | | refused, same message |
| **compound assignment — `l += 10`** | 250 + 10 | **260** — no check at all (loft#1009) |
| **`b: u8 = 5; b -= 10`** | | **-5**, in an unsigned type |
| struct field — `u.a += 253` from 7 | 260 | `0` — the write is refused and the type's default kept |
| vector element | 260 | `0`, the same |

So one program can hold 260 in a `u8` local and 0 in the `u8` field it was assigned from. Until loft#1009 closes, keep the arithmetic in an `integer` and discharge once: `l = ((n) as u8?) ?? 255`.

The storage half of the promise holds exactly: `u8` is 1 byte, `u16` 2, `i32`/`u32` 4, against `integer`'s 8, and a struct is their packed sum — `{ a: u8, b: u16, c: i8 }` is 4. A `vector<u8>` of three elements is three bytes.
