# @F38 — Arithmetic safety — overflow/÷0 → null, nullable peers

## What it is

When an INTEGER calculation cannot give a real answer — a number grows too big to hold, you divide by zero, or you take a remainder by zero — loft produces `null` for that result and keeps running, instead of crashing.

**Floats do not follow that rule.** `1.0 / 0.0` is `+inf` and `1.0e308 * 10.0` overflows to `inf`; both are *present* values, so `?? fallback` does not fire and the infinity flows on through every later sum and comparison. The one float division that answers null is `0.0 / 0.0`, because NaN is what loft uses for a null float — so whether `x / d ?? 0.0` defends anything depends on whether the numerator happened to be zero. For a float, test the divisor; `??` is the guard for the integer case (loft#983 tracks the remaining split between a raw quotient and a guarded one).

## How it aids you

One bad integer calculation no longer takes down the whole program. The trouble spot becomes a `null` you can spot and handle (often with `??` to supply a fallback), the way a spreadsheet shows an error in one cell while the rest of the sheet still works.

For a float the cell is not marked, which is what makes the divisor test worth writing: an infinity looks like a number all the way to the file you save.

## Example

```loft
fn main() {
    big: integer = 9_000_000_000_000_000_000;
    total = big + big;          // overflow -> null, no crash
    println("{total}");         // null
    divisor: integer = 0;
    safe = 100 / divisor ?? -1; // divide by zero -> null -> fallback
    println("{safe}");          // -1
    println("done");            // program keeps running
}
```
