# @F35 — String literals — `{expr}` interpolation + backtick multiline

## What it is

Text can carry values directly: write `{expr}` inside a string and its value is dropped in place. A brace you want to KEEP is doubled — `{{` and `}}` produce a literal `{` and `}` — which is the one thing to know before writing CSS, JSON or a shell snippet inside a string.

Strings in backticks may also span several lines, so the text you write looks like the text you get — including the indentation you gave it to fit the surrounding code.

## How it aids you

Building messages stays simple and readable — no clumsy joining of pieces with `+`. And multi-line strings let you lay out an email, a template, or a block of output exactly as it should appear.

**Indentation is the thing to plan for.** A backtick block that contains NO `{expr}` is dedented: exactly *(closing-backtick column − 1)* spaces come off each line, so a shader or a config block written flush against its closing backtick comes out at column 0. A block that contains even one `{expr}` is **not** dedented at all, and keeps its trailing blank line too — so a template with values in it arrives exactly as written, indentation and all. Write such a block flush to the left margin if the output must be flush (loft#990).

Two smaller edges of the dedent, both silent: a line indented LESS than the closing backtick keeps all of its indentation while its siblings lose theirs, and a TAB-indented line is never dedented at all.

## Example

```loft
fn main() {
    name: text = "world";
    n: integer = 3;
    println("Hello, {name}. You have {n} messages.");
    note: text = `first line
second line mentions {name}`;
    println(note);
    println("a literal brace: {{ {n} }}");
}
// Output:
// Hello, world. You have 3 messages.
// first line
// second line mentions world
// a literal brace: { 3 }
```
