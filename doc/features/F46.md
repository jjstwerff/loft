# @F46 — Type aliases (`type X = …`)

## What it is

`type Name = ...` gives an existing type a second, friendlier name. The alias and the original are the same type, so anywhere one works the other does too. It works for simple types, tuple types, and function types.

## How it aids you

Name a type for what it means in your program — `Celsius` instead of `float`, `Pair` instead of `(integer, text)` — so signatures read clearly and the intent is obvious at a glance.

## Example

```loft
type Celsius = float;
type Pair = (integer, text);

fn describe(temp: Celsius) -> text {
    "{temp} degrees"
}

fn main() {
    here: Celsius = 21.5;
    println(describe(here));         // 21.5 degrees
    basket: Pair = (3, "apples");
    println("{basket.0} {basket.1}");  // 3 apples
}
```


## "The same type" holds in both directions

Measured on both backends: a value declared with the alias is accepted where the original is wanted, and a value declared with the original is accepted where the alias is wanted. That is true for a scalar alias, a tuple alias, a function-type alias, and as the element type of a collection — there is no position where the two part company.
