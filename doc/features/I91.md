# @I91 — Language server (LSP) + parse-time resolution index

## What it does

Serves loft to an editor over the Language Server Protocol, so a plain text editor can
show live diagnostics and answer questions about the code it is displaying. The server
re-parses the buffer on every edit with a real stdlib-loaded parser — the same front end
the compiler uses — so what the editor reports is what the compiler would report, not a
second approximation of loft's rules.

Underneath it, the parser records what each identifier occurrence actually resolves to as
it parses. That index is what lets "what is this symbol?" and "where else is THIS binding
used?" be answered precisely rather than by matching names as text, which would confuse
two different variables that happen to share a name. Recording is gated behind a flag that
is off by default, so ordinary compilation pays nothing for it.

## Where it lives

`src/bin/loft-lsp.rs` (the LSP wire protocol over JSON-RPC / stdio; the binary owns
transport and locating the stdlib), `src/lsp.rs` (the library-side surface that calls the
compiler, so the compiler coupling stays out of the binary), `src/resolution.rs` (the
parse-time resolution index: position → resolved binding).
