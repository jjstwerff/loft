# @F96 — `x?` default-fallback operator — discharge a nullable to its type default

## What it is

Postfix `x?` turns a nullable value into a plain one by falling back to that type's **default** when it is null — `0` for a number, `""` for text, `false` for a boolean.

## How it aids you

When any sensible default will do, `x?` says so in one character, instead of spelling out `?? 0` at every use. It binds tightest, so `a.b?` reads the field then discharges it.

## Example

```loft
struct Config { retries: integer?, name: text? }

fn main() {
    c = Config { retries: null, name: null };
    println("retries {c.retries?}");   // retries 0
    println("name [{c.name?}]");       // name []
}
```

Types with no default (a struct without defaults for its fields) are a compile error rather than a guess. Use `??` when you want a *specific* fallback instead of the type's default.
